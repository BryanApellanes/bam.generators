# bam.generators.typescript

Generates TypeScript declarations from C# contract types, so REST and SignalR DTOs are defined once, in C#, and a consumer's CI can fail when the checked-in TypeScript drifts (bam.generators#37, bamscope ADR 0004). It renders through bam.generators' own Handlebars infrastructure (`TypeScriptContracts.hbs`, overridable from `./Templates`).

## Mappings

| C# | TypeScript |
|---|---|
| record, class or struct | `export interface` with `readonly` members |
| enum | string-literal union (`"A" \| "B"`) |
| struct wrapping one `string` (a typed id) | `string & { readonly __brand: "Name" }` |
| `T[]`, `List<T>`, `IReadOnlyList<T>`, `IList<T>`, `ICollection<T>`, `IReadOnlyCollection<T>`, `IEnumerable<T>` | `readonly T[]` |
| `IReadOnlyDictionary<string, T>`, `IDictionary<string, T>`, `Dictionary<string, T>` | `Readonly<Record<string, T>>` |
| `Nullable<T>`, nullable reference | `T \| null` |
| `string`, `char`, `Guid`, `DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`, `TimeSpan`, `Uri`, `byte[]` (base64) | `string` |
| integer and floating-point types, `decimal` | `number` |
| `bool` | `boolean` |

Types a property refers to are generated too, so passing the root messages is enough. Inherited properties are flattened, base class first.

## Naming
- Property names are camelCase by default (`JsonNamingPolicy.CamelCase`, ASP.NET Core's default), and `[JsonPropertyName]` always wins. A name that isn't an identifier is quoted.
- Enum members are written as declared by default (what `JsonStringEnumConverter` writes without a policy), and `[JsonStringEnumMemberName]` always wins.
- `[JsonIgnore]` (condition `Always`) leaves a property out.
- Both defaults can be changed through `TypeScriptGenerationOptions`.

## What it refuses
It throws a `TypeScriptGenerationException` naming the type and the property it was reached from, rather than emitting `any`. It refuses:
- `object`, interfaces, abstract types, and other `System` types without a mapping;
- generic contract types (declare a closed record instead);
- dictionaries keyed by anything other than `string`;
- multi-dimensional arrays;
- two types that would get the same TypeScript name.

## Things the generator can't check
- **Typed ids** are branded strings, so the C# side has to serialise them as plain strings. `System.Text.Json` writes a one-property struct as an object unless a `JsonConverter` writes it as its value.
- **Enums** are unions of names, so the API must use `JsonStringEnumConverter`, or the wire carries numbers.
- **`long`, `ulong` and `decimal`** map to `number`, which loses precision beyond 2^53.

## Determinism
- Declarations are sorted by name (ordinal), and members keep declaration order.
- Lines end in `\n`, there's no timestamp, and the file is UTF-8 without a byte-order mark.
- The first line is `// <auto-generated/>`.
- The same input gives the same bytes.

## From a console tool
```csharp
using Bam.Generators.TypeScript;

TypeScriptContractGenerator generator = new TypeScriptContractGenerator();
generator.WriteFile(
    "src/frontend/src/contracts/scope.ts",
    new[] { typeof(ScopeSnapshot), typeof(ScopeDelta) });
```
CI then regenerates and runs `git diff --exit-code` on the output. To generate from an assembly instead, `GetSource(assembly, type => type.Namespace == "Bam.Scope.Contracts")` selects the root types.
