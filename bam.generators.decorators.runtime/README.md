# bam.generators.decorators.runtime

The runtime that decorators generated by `bam.generators.decorators` run on. It holds `Decorator<I, T>`, `Decorator<T>`, the invocation context and result types, the handler stores, and the `IDecoratorLogger` abstraction. It depends on nothing but the BCL and targets `netstandard2.0` and `net10.0`, so an application on .NET Framework 4.7.2 or later can link a generated decorator without referencing the Bam framework.

Generating a decorator still takes the generator (`bam generate Decorator`, .NET 10). Generated with `WithoutRegistryExtensions()`, the output is plain C# that references only this package, so generate once and compile the result wherever it is needed. The output needs C# 9 or later (`#nullable enable`, unconstrained `T?`): a .NET Framework project sets `<LangVersion>9</LangVersion>` or higher.

## Install

```
dotnet add package bam.generators.decorators.runtime
```

## Use a generated decorator

```csharp
using Bam.Generators.Decorators;

EchoServiceDecorator decorator = new EchoServiceDecorator(new EchoService());
decorator.Subscribe(DecoratorPhase.Start, nameof(IEchoService.Message), ctx =>
{
    // ctx.Args, ctx.Method, ctx.Decorated
});
IEchoService echo = decorator;
```

Handlers run at `Start`, `End` and `Error`. A handler that returns a non-null value short-circuits the call (at start), replaces the result (at end), or supplies a fallback (on error). A handler that throws does not stop the call; the failure is reported through the decorator's logger and the call goes ahead. To stop a call, a handler calls `ctx.Reject(reason)` or throws `DecoratorRejectionException`.

The generated extensions class offers the same hooks as typed extension methods on the service: `echo.OnMessageStart(ctx => ...)`, `echo.OnMessageEnd(ctx => "replacement")`.

## Create decorators from a container

`DecoratorFactory` is the seam for a container of your own. Subscribe handlers once per service pair, and create decorators from the container's decoration hook; every decorator the factory creates for the pair runs the shared handlers, before the ones subscribed on the instance.

```csharp
DecoratorFactory.Handlers<IEchoService, EchoService>()
    .Add(DecoratorPhase.Error, nameof(IEchoService.Message), ctx => log.Warn(ctx.Exception));

// SimpleInjector, Microsoft.Extensions.DependencyInjection + Scrutor, or a plain factory lambda:
IEchoService Decorate(EchoService inner) => DecoratorFactory.Create<IEchoService, EchoService>(inner);
```

`Create<I, T>` finds the generated decorator among the loaded assemblies (`GeneratedDecorators.Find`: a class extending `Decorator<I, T>`, implementing `I`, with a `(T, IDecoratorLogger)` constructor; the conventional name `{T namespace}.Decorators.{T}Decorator` wins a tie) and throws `DecoratorException` when none is loaded. `Create<I, T, TDecorator>` names the type instead. Nothing is compiled.

A decorator generated from an interface alone (`DecoratorGenerator.AddInterface<I>()`, for an implementation generated code cannot name) is a `Decorator<I, I>` named `IEchoServiceDecorator`; `DecoratorFactory.Create<I>(instance)` and `DecoratorFactory.Handlers<I>()` are the `<I, I>` forms for it, and it wraps whatever implements `I`.

## Logging

The runtime reports handler failures through `IDecoratorLogger`, a one-method interface:

```csharp
public interface IDecoratorLogger
{
    void Error(string message, Exception? exception);
}
```

Pass an implementation to the decorator's constructor, or set `DecoratorLogger.Default` for every decorator constructed without one. The default is read when a failure is reported, not when the decorator is built, so it can be set after the container has already created decorators. Until something is set, the default is `TraceDecoratorLogger`, which writes to `System.Diagnostics.Trace`.

```csharp
DecoratorLogger.Default = new MyDecoratorLogger(serilog);
```

Hosts on the Bam framework get this for free: `bam.generators.decorators` installs an adapter over `Log.Default` the first time a registry is decorated, and `ILogger.ToDecoratorLogger()` wraps a specific logger.

## What is in which package

| Package | Targets | Holds |
|---|---|---|
| `bam.generators.decorators.runtime` | `netstandard2.0`, `net10.0` | Everything a generated decorator type references. |
| `bam.generators.decorators` | `net10.0` | The generator, the `ServiceRegistry` extensions, and the `ILogger` adapter. References the runtime and `bam.base`. |

A generated file holds two classes: the decorator and an extensions class with typed hooks. Generated with the default options, the extensions class also carries `ServiceRegistry` overloads that need `bam.generators.decorators`; generated with `WithoutRegistryExtensions()`, the whole file needs only this package.

## Build from source

The runtime is self-contained:

```bash
dotnet build bam.generators.decorators.runtime/bam.generators.decorators.runtime.csproj
dotnet build bam.generators.decorators.runtime.compat472/bam.generators.decorators.runtime.compat472.csproj   # net472 compile proof
./pack-runtime.sh            # packs to ~/.bam/build/pack/Release/
```
